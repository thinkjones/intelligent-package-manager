# ipm tui tabs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `ipm tui` opens on four workflow tabs — Catalog, Packs, Installs, Marketplace — each a tidy table with a detail pane, a stats strip and its own key bindings, and `/` filters the active tab.

**Architecture:** `internal/tui` keeps depending only on its own interfaces, which change shape: build is `Builder`, install (claude or gascity) is `Installer`, `Packs.List(global)` reports build state and installs, and a new `Marketplace` lists curated repos and follows them. The existing search+tree screen becomes the Catalog tab unchanged in behaviour. A shared `table.go` draws aligned, truncated columns with a header row; each tab is one file. The deploy modal becomes an install form that handles both targets. Adapters in `internal/cli/tui.go` call the CLI's functions, so the TUI adds no behaviour of its own.

**Tech Stack:** Go, Bubble Tea v2 (`charm.land/bubbletea/v2`), lipgloss v2, bubbles textinput; golden tests in `internal/tui/testdata/*.golden` (`go test ./internal/tui -run Golden -update`).

**Spec:** `docs/superpowers/specs/2026-10-14-ipm-workflow-commands-gascity-tui-design.md`, Part 3. Reference look: the user's `TuiDesign.png` (title line, tab bar with counts and the active tab highlighted, a coloured one-line stats strip, a header row over aligned columns, the selected row's details under the table, a one-line key footer).

## Global Constraints

- `internal/tui` imports no ipm package and no `System`; every new capability is an interface method implemented in `internal/cli/tui.go` by calling existing CLI functions (`runBuild`, `installClaude`, `installGascity`, `loadInstalls`, `buildCurrent`, `sourceAdd`, the `marketplace remove` code, `syncSources`/`runRebuild`, `curated.Fetch`/`curated.Parse`).
- Tab order and labels: `CATALOG (n)  PACKS (n)  INSTALLS (n)  MARKETPLACE (n)`; Catalog is the default. No All tab. Counts use thousands separators (`2,314`). A tab whose count is not loaded yet shows `(…)`.
- Layout top to bottom: title line (`ipm`, scope `project <path>` or `global`, `● hybrid` / `○ local` right-aligned); tab bar; one-line stats strip for the active tab; the tab body (table + detail pane); status line; key footer for the active tab. The palette in `style.go` is kept; `NO_COLOR` strips colour as today.
- Below `wideWidth` (100 columns) the detail pane hides; below `minWidth`×`minHeight` the existing "needs at least" message shows.
- Global keys (when no text input has focus): `1`–`4` and `[` / `]` switch tabs (wrapping); `/` focuses the active tab's filter (Catalog: the search box, as today); `?` help for the active tab; `q` quit; `ctrl+c` always quits. While a text input has focus, every printable key types into it and `esc` leaves it.
- Non-Catalog filter: case-insensitive substring over the row's visible column text; the stats strip shows `filter: <text>` while set; `esc` in the filter clears it.
- A tab whose data fails to load shows the error in its body; the other tabs keep working.
- Catalog keeps `a`/`d`, `p`/`n`, `t`, `f`, `e`, tree mode on `enter`/`tab` and ctrl+r. `b`, `i` and `D` leave the Catalog tab (build and install live on Packs and Installs).
- Packs tab: `g` include global packs (from a project scope), `x` remove the selected item (detail focus), `b` build every pack, `i` install the selected pack (opens the install form), `enter`/`→` focus the item list, `esc`/`←` back. Global packs shown from a project scope are read-only: `x`/`b`/`i` on them say `global pack — open ipm tui -g to change it`.
- Installs tab: `enter`/`i` reinstall the selected record, `a` new install (the install form: target claude or gascity), `g` include global records.
- Marketplace tab: `space` follow/unfollow the selected repo, `s` run catalog sync in the output modal; after a successful sync the status says `catalog synced — restart ipm tui to search the new items`.
- The build's success line is `✓ built`; an install's is `✓ installed <pack> (<target> …)`. No screen says "deploy" any more.
- Golden files are regenerated only with `-update` and their diffs are read before committing. Docs prose is never hard-wrapped. `docs/superpowers/` older files are history.
- Gate: `mise run verify`. Tests never touch the real home.

## Review Focus

1. Pressing `1`–`4`, `[`, `]`, `q`, `x`, `g`, `s` or `space` while the Catalog search box or a filter has focus must type, not switch tabs, quit, or act. Model test in Task 2 (search box) and Task 3 (filter).
2. A tab that fails to load (marketplace list offline with no cache, a broken `ipm.toml`) shows its error and the other tabs still work; switching back retries. Tests in Tasks 3 and 5.
3. Removing the last item in a pack, or the last pack row after a filter, must not leave the selection out of range (no panic, no blank detail). Tests in Task 3.
4. Starting an install or sync while one is already streaming must be refused (`busy — wait for the current run to finish`), not start a second pipe. Test in Task 4.
5. Very long names, repos and paths in every table are cut with `…` and columns stay aligned at 60, 100 and 160 columns. Goldens in Tasks 2–5 at 100 and 160, narrow at 60.

**Interfaces (produces):**

```go
type Builder interface { Build(ctx context.Context, out io.Writer) error }

// Target is where a pack is installed: Kind "claude" (Scope user|project|local,
// Path for project/local) or "gascity" (Path the parent folder, Name the folder).
// Global installs a pack of the user scope.
type Target struct {
    Kind, Scope, Path, Name string
    Global                  bool
}

type Install struct {
    Pack string
    Target
}

type Installer interface {
    Targets() []string                     // "claude", "gascity"
    Default(pack, kind string) Target
    Plan(pack string, t Target) (Target, []string, error) // the commands, for the confirm step
    Install(ctx context.Context, pack string, t Target, out io.Writer) error
    List(global bool) ([]Install, error)   // project records, plus global ones when global
}

type Pack struct {
    Name, Description string
    Items             []string
    Global            bool
    Built             string // "fresh", "stale" or "never"
    Installs          []Install
}

type Packs interface { /* Scope, Create, Add, Remove unchanged */ List(global bool) ([]Pack, error) }

type Repo struct {
    Repo, List, Description string
    Topics                  []string
    Stars, Items            int
    Followed                bool
}

type Marketplace interface {
    List() ([]Repo, error) // curated repos in list order, then followed repos no list holds under List "Other"
    Follow(repo string) error
    Unfollow(repo string) error
    Sync(ctx context.Context, out io.Writer) error
}

// Catalog gains Counts: items per type, for the tab count and stats strip.
type Catalog interface { Node(id string) (Node, error); Counts() map[string]int }

type Deps struct { Searcher Searcher; Catalog Catalog; Packs Packs; Builder Builder; Installer Installer; Marketplace Marketplace }
```
