# ipm install gascity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `ipm install gascity [pack]` writes a pack as a Gas City schema-2 pack folder that `gc lint` accepts, records the install, and prints the import snippet.

**Architecture:** The Claude build stays the source of truth for resolving and fetching: `.ipm/ipm.lock` pins every item, and `.ipm/node_modules` holds the repos. Whole local plugins now also pin their repo and record their parts (child skills, agents, commands, hooks and MCP servers) in the lock, so Gas City can expand them at the pinned commit. A new `internal/assemble/gascity.go` has three steps: `PlanGascity` (pure: names, expansion, skips), `RenderGascity` (reads the fetched files and returns the folder as an in-memory file list, so `--dry-run` and the golden tests share one path) and `WriteGascity` (temp sibling, refusal check, swap). `internal/cli/install_gascity.go` registers the `gascity` installer next to `claude`.

**Tech Stack:** Go 1.x, Cobra, `github.com/BurntSushi/toml` (encoder for `agent.toml` and `mcp/*.toml`), the existing `catalog.Frontmatter`.

**Spec:** `docs/superpowers/specs/2026-10-14-ipm-workflow-commands-gascity-tui-design.md`, Part 2 (and Part 1's install records).

## Global Constraints

- Command: `ipm install gascity [pack] [-C|--dir <parent>] [--name <name>] [-g] [--force] [--dry-run] [--update]`; also reachable as `ipm pack install gascity …` (the `install` command is already registered under `pack`).
- Output folder is `<dir>/<name>`; `-C` defaults to the working directory; `--name` defaults to the pack name and must match `^[A-Za-z0-9][A-Za-z0-9_-]*$` (else a `UsageError`, exit 2).
- `pack.toml` is exactly: line 1 `# generated by ipm — rewritten by ipm install gascity; do not edit`, then one `# <item id> @ <commit>` line per picked item sorted by ID (`@ -` when the item has no commit), then `[pack]` with `name`, `schema = 2`, `version = "0.0.0-ipm"`, and `description` only when the pack has one. No other keys: Gas City rejects unknown keys.
- Layout: `skills/<skill>/…` (skill folder copied whole), `agents/<agent>/prompt.md` + `agents/<agent>/agent.toml`, `mcp/<server>.toml`.
- Agents: body without frontmatter goes to `prompt.md` (confirmed in `gastownhall/gascity` `internal/config/config.go`: "plain .md remains inert", so `{{` is not templated). `agent.toml` has `description` (when set), `provider = "claude"`, and `[option_defaults] model = "<model>"` when the frontmatter `model` is set and not `inherit`. Every other frontmatter key except `name` is dropped with one warning per agent: `agents/<name>: dropped tools, color — Gas City agents have no equivalent` (keys sorted, comma-separated).
- MCP (confirmed in `internal/materialize/mcp.go`): fields `name`, `description`, `command`, `args`, `env`, `url`, `headers`; `name` must equal the file stem and match `^[a-z0-9-]+$`; exactly one of `command` or `url`. Claude's `type` key is dropped silently; any other unknown key is dropped with a warning `mcp/<name>: dropped <keys>`; a value containing `${CLAUDE_PLUGIN_ROOT}` warns `mcp/<name>: uses ${CLAUDE_PLUGIN_ROOT}, which Gas City does not set`.
- Skip messages, verbatim: `skipped <id>: Gas City has no slash commands`, `skipped <id>: Gas City packs have no hooks`, `skipped <id>: external plugin — its files live in another repo; add its skills and agents directly`.
- Names: skills and agents are sanitised to `[a-z0-9_-]` (lowercase, other runs → `-`, trimmed of `-` and `_`); MCP servers to `[a-z0-9-]`. Clashes within a kind use the existing rule: `-<owner>`, then `-2`, `-3`.
- Files are copied, never hard-linked; file modes are kept.
- Writes go to `<dir>/.<name>.ipm-tmp`, then swap in. A target that exists, is non-empty and whose `pack.toml` does not start with the header line is refused with exit 1 — `<path> exists and was not written by ipm — use --force to replace it` — unless `--force`.
- After writing: record `{target: "gascity", path: <dir, absolute>, name: <name>}` and print the snippet (see Task 5).
- `--dry-run` writes nothing (no build, no folder, no record) and needs a current build: `--dry-run needs a current build — run ipm pack build first`.
- Two runs give byte-identical folders.
- Tests never touch the real home: `IPM_HOME`/`IPM_CACHE_DIR` absolute temp paths. Gate: `mise run verify`.
- Don't hard-wrap prose in markdown. `docs/superpowers/` older files are history; don't edit them.

## Review Focus

1. A whole plugin's MCP server whose args use `${CLAUDE_PLUGIN_ROOT}` (common: servers shipped inside the plugin) — the user expects a warning, not a silently broken server. Test in Task 3.
2. Re-running `ipm install gascity` over its own earlier output, and over a hand-made folder of the same name — the first replaces cleanly (removed items leave no files), the second is refused without `--force`. Tests in Task 4.
3. A lock written by PR 1 (whole plugin without `parts`) — the next build fills `parts` from the catalog and keeps the pinned SHA; Gas City never reads the catalog's newer commit. Test in Task 1.
4. Two items whose sanitised names collide across kinds' rules (e.g. agent `Code.Review` and `code-review`, MCP server `My_Server`) — distinct folders, valid names. Tests in Tasks 2 and 3.
5. A symlink inside a fetched skill or plugin that points outside its repo — refused like the Claude build refuses it. Test in Task 3.
